# Модели из Blender: сборка, стиль, импорт в Roblox

Все модели построек собираются скриптами Blender — без ручного моделинга, поэтому любой ассет можно
пересобрать одной командой, а стиль у всех одинаковый.

```
art/
  palette.json            палитра: ключ → цвет + Enum.Material (общая для Blender и игры)
  blender/
    kit.py                библиотека моделинга: фаски, тела вращения, гладкие каркасы, листья, текст, анимации
    build.py              сборка: рендер превью, экспорт FBX/GLB, склейка деталей
    palette_luau.py       palette.json → src/shared/Config/Palette.luau
    assets/agro.py        грядки, лоток скупщика, авто-вышка, авто-грядка T1, спринклер
    assets/agro2.py       забор, авто-лейка, мешок XL, фитолампы, авто-грядки T2/T3, вывеска, солнечная крыша…
    assets/agro3.py       гидропоника, аэропоника, теплицы, удобрения, датчики, ионизатор, флаг, маскот
    assets/energy.py      бензогенератор, малый ветряк
    assets/energy2.py     дизели, биогаз, турбина, трекер, большой ветряк, геотермия, подстанция,
                          аккумуляторы, реакторы, офис, станция дронов, ИИ-сортировщик, градирня, рубильник
    assets/factory.py     слайсер
    assets/factory2.py    корпус цеха и модули-множители, квантовый преобразователь
    assets/science.py     лаборатория, центрифуга, мутагенез, инкубатор, облучатель, голотерминал,
                          крио-хранилище, монумент, пусковая вышка, маяк, спутник, терминал звёзд
    assets/misc.py        дрон, колорадский жук, стартовая площадка, шаттл
    assets/misc2.py       объекты площади (статуя, зал славы, ворота Rebirth…), робот, фонарь, ель
  previews/<Ключ>.png     рендеры Cycles
  previews/<Ключ>.gif     анимации (2 секунды, по кругу)
  export/fbx/<Ключ>.fbx   по файлу на ассет — для 3D Importer в Roblox Studio
  export/glb/<Ключ>.glb   ассет с анимацией (открывается в любом glTF-просмотрщике)
  export/manifest.json    детали каждого ассета и число треугольников
  PotatoTycoon_Assets.blend исходная сцена (до склейки деталей) для правки руками
```

## Сборка

Нужен Blender 4.2 LTS (работает без интерфейса).

```bash
# всё: превью + экспорт (≈ 12 минут на 4 ядрах)
blender -b --python art/blender/build.py -- --samples 40 --res 960x720 --save art/PotatoTycoon_Assets.blend

# один-два ассета, только экспорт
blender -b --python art/blender/build.py -- --only BedWood,Drone --no-render

# кадры анимации → GIF
blender -b --python art/blender/build.py -- --only Drone --no-export --frames --samples 12 --res 480x360
python3 art/blender/gif.py Drone
```

Ключ ассета = `model` из `src/shared/Config/Items.luau` (для служебных моделей — `Drone`, `Bug`).

## Стиль

- **Гладкие формы, а не сборка из примитивов.** Корпуса — коробки с фасками (bevel + harden normals),
  круглые детали — тела вращения по профилю (`k.lathe`): баки, сопла, моторы, лампы, мешки.
  Органика (клубни, камни, голова жука) — низкополигональный каркас + Subdivision Surface (`k.blob`, `k.cage`).
  Никаких «облаков» из сфер.
- **Растения — из настоящих листьев.** Куст картофеля: 9 сложных листьев (черешок, 3 пары листочков и
  верхушечный), стебли-трубки, цветы из 5 лепестков с жёлтым конусом тычинок.
- **Надписи — объёмный текст** (`k.text`), а не текстуры.
- **Один объект — один материал из палитры.** Цвета не задаются в коде ассета, только ключ палитры.
- **Масштаб и оси:** 1 единица Blender = 1 стад; пол — z = 0; «лицо» ассета смотрит в −Y
  (в игре это +Z — к входу на базу); габариты совпадают с `size` предмета в каталоге.

## Имена деталей и анимации

После склейки в каждой детали (будущая MeshPart) остаётся всё, что нужно игре:

```
Путь/Групп__КлючПалитры[@анимация][#x,y,z]
Body__WoodDark                                   корпус
Bush/Plant0__Leaf@sway_x_2.5_3.14_0.15#0.05,0.85,-2   листья куста, покачивание вокруг точки (x,y,z)
Lamp1-1__NeonRed@pulse_1.5                       мигающая лампа
Origin__Pivot                                    калибровочный куб 1×1×1 в начале координат
```

| Анимация | Смысл | Тег в игре |
|---|---|---|
| `spin_<ось>_<град/с>` | вращение (лопасти, радар, шнек) | `Spin` |
| `sway_<ось>_<град>_<рад/с>[_фаза]` | покачивание (кусты, лапы жука) | `Sway` |
| `bob_<амплитуда>_<рад/с>[_фаза]` | вверх-вниз (дрон, чаша весов) | `Bob` |
| `slide_<ось>_<стадов>_<рад/с>[_фаза]` | вперёд-назад (чипсы на ленте, вибрация мотора) | `Slide` |
| `pulse_<скорость>` | мигание неона | `Pulse` |

Оси — уже в системе Roblox. Фаза — доля цикла: так шесть лап жука идут «треногой».
Группы `Bush`, `Tubers`, `Stack`, `Flames` игра находит по имени: рост кустов, клубни при созревании,
старт шаттла и пламя двигателей.

Разбор имён — `src/shared/AssetName.luau`, установка моделей — `src/server/World/Templates.luau`.

## Импорт в Roblox Studio

1. Откройте место (`rojo build` → `PotatoTycoon.rbxlx` или ваш опубликованный плейс).
2. **Home → Import 3D**, выберите `art/export/fbx/BedWood.fbx` (можно по одному или все файлы сразу).
   Единицы импорта не важны: игра находит масштаб по кубу `Origin__Pivot`.
3. В **ServerStorage** создайте папку **`Assets`** и перенесите туда импортированные модели.
   Имя модели должно совпадать с ключом (`BedWood`, `Drone`, `Bug`…) — Studio так и называет её по имени файла.
4. Запустите игру. Для каждого ключа, у которого есть модель в `ServerStorage.Assets`,
   постройка собирается из неё; остальные постройки остаются процедурными.

Что происходит при постройке (`Templates.dress`):

- процедурный строитель по-прежнему создаёт подсказки (`ProximityPrompt`), атрибуты, свет и дым —
  детали-носители становятся невидимыми и проходимыми, чисто декоративные удаляются;
  табло с живым текстом (`SurfaceGui` со своим именем) остаётся как есть;
- детали шаблона копируются и получают цвет и материал из `Config.Palette`; корпус сталкивается с игроком
  (коллизия по форме меша), а кусты, клубни, пламя и всё анимированное — нет;
- анимируемые группы становятся моделями с тегами `Spin`/`Sway`/… — их проигрывает клиентский `Animator`;
- дрон и робот перекрашиваются в цвет сотрудника, жук-босс увеличивается в 3 раза, ели — по размеру дерева.

NPC (скупщик, дед Матвей, персонал) — не модели из Blender, а настоящие аватары R15
(`Kit.avatarize`: цвета одежды, шляпа, борода, анимация ожидания). Аватар создаётся, когда игра
запущена в Roblox; в тестах без Roblox остаётся простая фигурка.

Если модель импортирована «плоско» (без вложенных групп) — это не важно: путь групп записан в именах.

## Бюджет

- До 10 000 треугольников на деталь (лимит Roblox — 20 000), детали склеены по материалу внутри группы:
  грядка — около 20 MeshPart вместо 300 объектов.
- Число треугольников по ассетам — в `art/export/manifest.json`.

## Добавить новый ассет

1. Функция `def my_asset(k, root)` в подходящем `art/blender/assets/*.py`
   (детали — через `k.box`, `k.lathe`, `k.blob`, `k.tube`, `k.text`…, анимация — `k.tag(группа, k.spin(...))`).
2. Строка в `ASSETS` в `art/blender/build.py`: ключ (как `model` в каталоге), функция, ракурс превью.
3. Сборка с `--only MyAsset`, проверить превью, импортировать FBX в `ServerStorage.Assets`.
